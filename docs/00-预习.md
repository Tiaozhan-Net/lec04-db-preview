
## 1. 安装 MySQL 8.0

这一节只给检查清单，不展开安装细节。

1. 打开 MySQL 官方下载页，下载 **MySQL Installer for Windows**。
2. 安装类型选 **Server only** 即可。
3. 配置时注意三件事：
   - 端口用默认的 `3306`；
   - 设置并记住 `root` 密码；
   - 勾选把 MySQL 注册为 Windows 服务。
4. 安装完成后记住 root 密码，下一步打开命令行。

> 已经装过 MySQL 8.0 的同学跳过这一节。

## 2. 打开 MySQL 命令行

### 2.1 先试 `mysql` 命令

打开 PowerShell 或 Windows Terminal，输入：

```powershell
mysql -u root -p
```

回车后输入安装 MySQL 时设置的 root 密码。

看到下面这个提示符，就说明登录成功：

```text
mysql>
```

再执行：

```sql
SELECT VERSION();
```

执行结果：

```text
+-----------+
| VERSION() |
+-----------+
| 8.0.44    |
+-----------+
1 row in set (0.00 sec)
```

看到 `8.0.x` 就说明连上了。你的版本号可能不是 `8.0.44`，只要以 `8.0` 开头就可以。

### 2.2 如果提示找不到 `mysql`

如果 Windows 提示：

```text
'mysql' 不是内部或外部命令，也不是可运行的程序
```

说明 `mysql.exe` 不在 PATH 里。两种办法：

1. **用开始菜单（推荐）**：开始菜单 → **MySQL 8.0 Command Line Client** → 输入 root 密码。
2. **配 PATH**：找到 MySQL 安装目录下的 `bin` 文件夹，把完整路径加到系统环境变量 `Path`，然后重新打开终端。
   - 复制 `bin` 文件夹的完整路径；
   - 此电脑 → 右键“属性” → 高级系统设置 → 环境变量；
   - 在“系统变量”里选中 `Path` → 编辑 → 新建 → 粘贴路径 → 确定；
   - 关闭并重新打开 PowerShell，再试 `mysql -u root -p`。

注意：MySQL 不一定装在 C 盘，不要照抄别人的 `C:\Program Files\...`。去开始菜单找，或者在自己的安装目录下找 `bin`。

### 2.3 先认识提示符

| 看到 | 含义 | 怎么办 |
| --- | --- | --- |
| `mysql>` | 可以输入 | 输入 SQL，末尾加 `;` 执行 |
| `->` | 语句还没结束 | 继续输入，或补 `;`；不想执行就输入 `\c` |
| `'>` | 单引号没闭合 | 补 `'`，或输入 `\c` 取消 |
| `">` | 双引号没闭合 | 补 `"`，或输入 `\c` 取消 |

记住三件事：

- **每条 SQL 以 `;` 结尾才会执行**；
- 字符串用英文单引号 `'张三'`，不要用中文引号 `‘张三’`；
- `\c` 取消当前没写完的语句，`\q` 或 `exit` 退出。

### 2.4 复制和粘贴

- Windows Terminal：`Ctrl+Shift+V`
- PowerShell：`Ctrl+V`
- 旧版 cmd：右键粘贴

可以一次粘贴多条 SQL，MySQL 会在每个 `;` 处执行。如果粘贴后看到 `->`，说明还差一个分号。

## 3. 建练习库，执行 init.sql

### 3.1 建库

先在 `mysql>` 里建库：

```sql
CREATE DATABASE IF NOT EXISTS preview CHARACTER SET utf8mb4;
```

切换到 `preview`：

```sql
USE preview;
```

确认当前数据库：

```sql
SELECT DATABASE();
```

`CREATE DATABASE` 成功会显示 `Query OK`，`USE` 成功会显示 `Database changed`。最后一条查询应该返回 `preview`。如果数据库已经存在，`CREATE DATABASE` 的输出可能略有不同，只要没有报错即可。

### 3.2 建表并插入 5 行数据

打开 `preview/init.sql`，看一眼内容，然后在 `mysql>` 里手动敲，或者复制进去。

先建表：

```sql
DROP TABLE IF EXISTS members;

CREATE TABLE members (
  id         BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  name       VARCHAR(64)     NOT NULL,
  class_name VARCHAR(32)     NOT NULL,
  major      VARCHAR(32)     NOT NULL,
  score      DECIMAL(5,2)    NOT NULL DEFAULT 0,
  joined_at  DATETIME(3)     NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  PRIMARY KEY (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

建表成功会显示 `Query OK`。第一次执行 `DROP TABLE` 时表还不存在，可能多一个 warning，正常。`CREATE TABLE` 这一段建议手敲一遍，能发现引号、逗号、分号的问题。

再插入 5 行数据：

```sql
INSERT INTO members (id, name, class_name, major, score) VALUES
(1, '张三', '2023-1', '计算机', 78),
(2, '李四', '2023-2', '数学', 88),
(3, '王五', '2024-1', '计算机', 92),
(4, '赵六', '2024-2', '英语', 65),
(5, '钱七', '2022-1', '计算机', 85);
```

插入成功会显示 `Query OK, 5 rows affected`。`INSERT` 比较多，可以直接复制。

执行完检查：

```sql
SHOW TABLES;
```

应看到 `members`。

```sql
DESCRIBE members;
```

应看到 `id`、`name`、`class_name`、`major`、`score`、`joined_at` 六个字段。

```sql
SELECT * FROM members;
```

最后一条查询的结果：

```text
+----+------+------------+--------+-------+-------------------------+
| id | name | class_name | major  | score | joined_at               |
+----+------+------------+--------+-------+-------------------------+
|  1 | 张三 | 2023-1     | 计算机 | 78.00 | 2026-10-18 20:15:40.414 |
|  2 | 李四 | 2023-2     | 数学   | 88.00 | 2026-10-18 20:15:40.414 |
|  3 | 王五 | 2024-1     | 计算机 | 92.00 | 2026-10-18 20:15:40.414 |
|  4 | 赵六 | 2024-2     | 英语   | 65.00 | 2026-10-18 20:15:40.414 |
```

应该看到 5 行数据。`joined_at` 是你执行时的时间，耗时数字也会因机器不同而变化，行数和字段值一致即可。

`init.sql` 可以重复执行。**改坏了就整段重跑一次**，数据会回到 5 行。

### 4.2 修改一条

打开 `preview/02_update.sql`，在 `mysql>` 里执行。

先查，确认改的是谁：

```sql
SELECT id, name, score FROM members WHERE id = 1;
```

查出来是 `78.00`。

再改：

```sql
UPDATE members SET score = 80 WHERE id = 1;
```

`UPDATE` 成功时会显示 `Query OK, 1 row affected`。

再查，确认改对了：

```sql
SELECT id, name, score FROM members WHERE id = 1;
```

最后一条查询的结果：

```text
+----+------+-------+
| id | name | score |
+----+------+-------+
|  1 | 张三 | 80.00 |
+----+------+-------+
1 row in set (0.00 sec)
```

**重点**：`UPDATE` 一定要带 `WHERE`。

```sql
-- 不要执行！这会把所有人的分数改成 0
UPDATE members SET score = 0;
```

## 5. 条件查询

打开 `preview/05_select.sql`，一条一条执行。

```sql
-- 全部
SELECT id, name, score FROM members;

-- 比较
SELECT id, name, score FROM members WHERE score >= 85;

-- 字符串
SELECT id, name, major FROM members WHERE major = '计算机';

-- 模糊
SELECT id, name FROM members WHERE name LIKE '张%';

-- 范围
SELECT id, name, score FROM members WHERE score BETWEEN 80 AND 90;

-- 多选
SELECT id, name, major FROM members WHERE major IN ('计算机', '数学');

-- 组合
SELECT id, name, score FROM members
WHERE major = '计算机' AND score >= 85;

-- 排序 + 截断
SELECT id, name, score FROM members
ORDER BY score DESC, name ASC
LIMIT 3;

-- 计数
SELECT COUNT(*) AS cnt FROM members;

-- 分组
SELECT major, COUNT(*) AS cnt FROM members GROUP BY major;
```

练习方法：每条先照抄跑通，然后改一个条件再跑。

- 把 `>= 85` 改成 `>= 90`；
- 把 `'计算机'` 改成 `'数学'`；
- 把 `LIMIT 3` 改成 `LIMIT 2`；
- 把 `'张%'` 改成 `'%三'`。

## 6. 常见错误

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `mysql` 不是内部或外部命令 | 没配 PATH | 用开始菜单的 MySQL 8.0 Command Line Client，或把 `bin` 加进 PATH |
| `Access denied for user 'root'` | 密码错 | 重新执行 `mysql -u root -p` |
| `No database selected` | 没选库 | `USE preview;` |
| `Unknown database 'preview'` | 库没建 | `CREATE DATABASE IF NOT EXISTS preview CHARACTER SET utf8mb4;` |
| `Table 'preview.members' doesn't exist` | 表没建 | 先执行 `init.sql` |
| `ERROR 1064` | 语法错 | 检查中文引号、逗号、分号 |
| `ERROR 1050 Table 'members' already exists` | 表已存在 | 先 `DROP TABLE IF EXISTS members;` 再建 |
| `->` | 语句没结束 | 补 `;`，或输入 `\c` |
| 查询结果多出很多重复行 | 演示脚本重复执行了 | 重跑 `init.sql` |
| 所有人的分数都被改了 | `UPDATE` 忘了写 `WHERE` | 重跑 `init.sql`，重新来 |
| 整张表空了 | `DELETE` 忘了写 `WHERE` | 重跑 `init.sql`，重新来 |

三条保命习惯：

1. `UPDATE` / `DELETE` 之前，先用同样的 `WHERE` 跑一次 `SELECT`。
2. `UPDATE` / `DELETE` 必须带 `WHERE`。
3. 改坏了就重跑 `init.sql`，不要手工修数据。

## 7. 作业

题目、文件清单和本地自测方法在 [homework/README.md](../homework/README.md)。

这次作业的提交方式和以前不同：不再往模板仓库里交文件，而是通过 **Pull Request（PR）** 提交。

PR 是 GitHub 上很常见的一种多人协作方式。你先把改动提交到自己 fork 出来的仓库的某个分支上，再向老师的仓库发起一次"合并申请"；老师和自动测评程序在网页上就能直接看到你改了哪些文件、有没有通过检查，确认没问题后再由老师合并进主仓库。整个过程不用发邮件、传压缩包，也不会直接改动老师的仓库。

具体怎么开 PR，请看第 8 章。PR 开好之后会自动运行 `autograde` 测评：**测评通过就算作业完成**，稍后老师会手动合并。

### 7.1 要做的事

1. 在 GitHub 上 Fork 老师的仓库；
2. 把仓库 clone 到本地，并把老师的仓库添加为 upstream；
3. 新建一个以自己 GitHub 用户名为名的分支；
4. 把 `homework/templates/` 里的 6 个文件复制到 `submissions/<你的 GitHub 用户名>/`；
5. 按文件里的注释和 `homework/README.md` 完成 SQL 和 README；
6. `git commit` 并 `git push`；
7. 在 GitHub 上开 Pull Request；
8. 看 `autograde` 结果，红了就改完再 push。

> 第 8 步之后，在同一个 PR 里继续 `commit` + `push` 会自动重新测评，不需要再开一次 PR。

### 7.2 三条硬性要求

- 分支名、目录名、PR 标题里的用户名都用 GitHub 用户名，不要写学号或真实姓名；
- 只修改 `submissions/<你的 GitHub 用户名>/` 下的文件；
- 评测读的是文件，不是你的命令行历史；作业会在另一份数据上评测，不要写死查询结果。

## 8. 提交 PR

### 8.1 第一步：Fork 仓库

打开课程仓库页面，点右上角 **Fork**，把仓库复制到你自己的 GitHub 账号下。

做完检查：你的浏览器地址栏里，仓库拥有者变成了你自己的用户名，形如 `https://github.com/<你的 GitHub 用户名>/db-preview`。

### 8.2 第二步：Clone 到本地并添加 upstream

```bash
git clone <你的 Fork 仓库地址>
cd db-preview
git remote add upstream <老师的仓库地址>
git remote -v
```

尖括号和里面的中文要整段替换：`<你的 Fork 仓库地址>` 换成 8.1 里得到的地址，`<老师的仓库地址>` 换成老师给的地址。

做完检查：`git remote -v` 应该输出四行，两行 `origin` 指向你自己的 fork，两行 `upstream` 指向老师的仓库。

> 命令是 `git remote add`，不是 `git add remote`。

### 8.3 第三步：建分支

```bash
git fetch upstream
git checkout -b <你的 GitHub 用户名> upstream/main
git branch
```

把 `<你的 GitHub 用户名>` 整段换成你的用户名，不要保留尖括号。

做完检查：`git branch` 的输出里带 `*` 的就是当前分支，名字应该是你的 GitHub 用户名。分支必须从 `upstream/main` 开，不要从自己 fork 的 `main` 开。

### 8.4 第四步：复制模板文件

在文件管理器里进入 `db-preview` 目录，在 `submissions/` 下新建文件夹 `<你的 GitHub 用户名>`，然后把 `homework/templates/` 下的 6 个文件复制进去：

```text
01_dml.sql
02_q1_score.sql
03_q2_major.sql
04_q3_like.sql
05_q4_top3.sql
README.md
```

文件名不要改。

做完检查：`submissions/<你的 GitHub 用户名>/` 下正好这 6 个文件，文件夹名和你 GitHub 上的用户名一致（只写登录名，不要加 `@` 或邮箱）。

### 8.5 第五步：完成作业

打开 `homework/README.md` 看题目，再按每个文件里的注释写：

- `01_dml.sql`：四条增删改语句，其中新增记录的 `name` 写你的 GitHub 用户名；
- `02_q1_score.sql` 到 `05_q4_top3.sql`：每个文件有且只有一条 `SELECT`，按注释要求写列、排序和 `LIMIT`，不要用 `SELECT *`；
- `README.md`：写上 GitHub 用户名，并在三个 `答：` 的同一行后面写回答。

模板里只有注释，语句要自己写。可以对照 `preview/` 下对应的示例，但建议自己敲一遍。**不要把 `mysql>`、`->` 这些提示符也复制进去。**

写完先在本地自测，方法见 `homework/README.md` 的「本地自测」。

### 8.6 第六步：提交并推送

```bash
git status
git add submissions/<你的 GitHub 用户名>
git commit -m "hw: <你的 GitHub 用户名>"
git push -u origin <你的 GitHub 用户名>
```

做完检查：`git status` 里列出的应该只有你目录下的文件，没有 `preview/`、`homework/` 或别人的 `submissions/`。`git push` 成功会显示分支已建立并跟踪 `origin`。

### 8.7 第七步：开 Pull Request

回到 GitHub 上你自己的 fork，点 **Compare & pull request**。

- base 仓库：老师的仓库
- base 分支：`main`
- head 分支：`<你的 GitHub 用户名>`
- 标题：`hw: <你的 GitHub 用户名>`

PR 描述按模板把能勾的勾上，用户名那一栏填你的 GitHub 用户名。

第一次提交 PR 可能显示 **Pending approval**，这是正常的，等老师批准，不用重复提交。

### 8.8 第八步：看评测结果

在 PR 页面往下找 `autograde` 检查项。

- 绿色：通过。等老师合并，不要自己 merge。
- 红色：点 `Details`，看 `Summary` 表格里每一项的期望值和实际值，改完文件后回到 8.6 重新提交。

> **改了不用重新开 PR**：在同一个分支上继续 `git add` + `git commit` + `git push`，`autograde` 会自动重新跑一遍，不需要关掉 PR 重开，也不需要再点一次 Pull Request。

### 8.9 不要做的事

- 不要改 `preview/`、`homework/`、`grader/`、`.github/`；
- 不要改别人的 `submissions/` 目录；
- 不要提交 zip、`.idea`、`node_modules`；
- 不要直接在 GitHub 网页上改完就 merge 到自己的 `main` 再开 PR，分支要从 `upstream/main` 开。

## 10. 常见问题

### Q1：`autograde` 一直 Pending 怎么办？

第一次向仓库提交 PR，GitHub 需要维护者批准 workflow。等老师点一下即可，不用重复提交。

### Q2：`autograde` 红了，但不知道错在哪？

点 check 旁边的 `Details`，看 `Summary` 里的表格。每一项都会写期望值和实际值。

### Q3：我本地跑出来是对的，为什么评测不对？

评测会重置数据库，并使用另一份数据跑查询。检查：

- 查询里有没有写死姓名或分数；
- 有没有漏 `ORDER BY`；
- 列名、列顺序是否和题目一致；
- 有没有多写 `SELECT *`；
- 文件里有没有混进 `mysql>` 或 `->` 提示符。

### Q4：提示 `mysql` 不是内部或外部命令怎么办？

用开始菜单里的 **MySQL 8.0 Command Line Client**，或者找到 MySQL 安装目录下的 `bin`，把它加进系统环境变量 `Path`。MySQL 不一定装在 C 盘，不要照抄路径。

### Q5：MySQL 装的是 5.7，可以吗？

最好装 8.0。课程里的函数索引、`utf8mb4` 默认排序规则等都以 8.0 为准。

### Q6：可以只交 SQL，不写 README 吗？

不可以。README 占 10 分，也用来确认 GitHub 用户名。

### Q7：可以改 `preview/init.sql` 方便自己练习吗？

本地可以，但**不要提交到 PR**。PR 里只允许改 `submissions/<你的 GitHub 用户名>/` 下的文件。

### Q8：怎么退出 MySQL 命令行？

输入 `\q` 或 `exit`。

## 附录：Navicat（可选）

### Navicat 是什么

Navicat 是一个**数据库图形客户端**，不是数据库本身。真正存数据的是 MySQL 服务，Navicat 只是连接到 MySQL，用窗口和表格代替命令行操作，例如：

- 点开数据库和表，直接查看数据；
- 在表格里新增、修改、删除行；
- 在查询窗口里写 SQL；
- 导入、导出数据。

### 一定要装吗

**不用。** 本课程的预习和作业都可以在 `mysql>` 命令行里完成，命令行也是最通用、最接近实际工作的方式。装 Navicat 只是让看表和改数据更直观，属于可选工具。

### 收费说明

Navicat 是商业软件，需要付费，官网通常只提供有限天数的试用版。

### 安装过程

1. 打开 Navicat 官网，下载 Windows 版安装包；
2. 双击安装包，按默认选项完成安装；
3. 打开 Navicat，新建 MySQL 连接：
   - 主机：`127.0.0.1` 或 `localhost`
   - 端口：`3306`
   - 用户名：`root`
   - 密码：安装 MySQL 时设置的 root 密码
4. 连接成功后，应该能看到 `preview` 数据库和 `members` 表；
5. 右键数据库，选择 **新建查询**，就可以写 SQL，效果和 `mysql>` 一样。

> 课程不要求提交 Navicat 的截图或工程文件，作业仍然只提交 `.sql` 和 `README.md`。
